# JustTracker — системная спецификация (системный аналитик)

## 1. Сценарии использования

### UC-01. Запись трека
**Актёр:** пользователь. **Предусловие:** приложение открыто на экране «Запись».
**Основной поток:**
1. Пользователь нажимает «Старт».
2. Система проверяет разрешение `ACCESS_FINE_LOCATION`; при отсутствии — UC-05.
3. Система проверяет, включён ли провайдер GPS; при выключенном — предлагает открыть настройки, сценарий приостанавливается.
4. Система создаёт запись `Track(status=RECORDING, startedAt=now)` в БД и запускает `TrackingService` в foreground с уведомлением.
5. Сервис подписывается на Fused Location Provider (интервал 1 с, минимальный 500 мс, `PRIORITY_HIGH_ACCURACY`).
6. Каждая полученная точка проходит фильтр (§3.1); принятые сохраняются в `TrackPoint`.
7. UI наблюдает БД и обновляет карту и метрики.
8. Пользователь нажимает «Стоп» → подтверждение → `Track.status=FINISHED, finishedAt=now`, статистика пересчитывается и сохраняется, сервис останавливается, открывается экран деталей.

**Альтернативные потоки:**
- 6a. Потеря сигнала GPS > 10 с: UI показывает «Поиск GPS»; сервис продолжает ждать; при восстановлении новые точки добавляются в тот же сегмент, если разрыв < 60 с, иначе открывается новый сегмент (линия не соединяется).
- 6b. Пользователь отзывает разрешение во время записи (через настройки): FLP перестаёт поставлять точки; при возврате в приложение UI показывает баннер «Разрешение отозвано» с кнопкой запроса; сервис остаётся живым до «Стоп».
- 6c. Система убивает процесс: сервис имеет `START_STICKY`; при перезапуске сервис читает из БД трек со статусом `RECORDING`/`PAUSED` и продолжает запись новым сегментом. Если сервис не перезапущен (например, force-stop), при следующем запуске UI видит трек `RECORDING` без живого сервиса и предлагает «Продолжить» / «Завершить».
- 6d. Перезагрузка устройства: сервис не перезапускается автоматически (без `RECEIVE_BOOT_COMPLETED` в MVP); поведение как в 6c при следующем запуске приложения.
- 6e. Нехватка места: `SQLiteFullException` перехватывается, запись автоматически завершается со статусом FINISHED, показывается уведомление об ошибке.
- 8a. Трек < 2 точек: трек удаляется, сообщение «Слишком мало данных».

### UC-02. Пауза / продолжение
1. «Пауза» → `Track.status=PAUSED`, сервис отписывается от FLP, но остаётся foreground; уведомление «Пауза».
2. «Продолжить» → `segmentIndex++`, подписка на FLP восстанавливается.

### UC-03. Просмотр истории и деталей
1. Список: `SELECT * FROM tracks WHERE status='FINISHED' ORDER BY startedAt DESC`; пока первая выборка не пришла дольше 100 мс — скелетон списка.
2. Детали: загрузка трека и всех его точек (два параллельных Flow из Room), построение полилиний по сегментам с окраской по скорости (§3.6), fit bounds с отступом 48 dp; тап по линии → курсор. Состояние экрана собирается, как только пришли трек, точки и настройки; метки «Интересного рядом» (сеть) стартуют с пустого списка и **не входят в условие готовности** — Overpass может отвечать десятки секунд или молчать (паузы 15/60 с), экран при этом уже показан. Пока данные читаются дольше 100 мс — скелетон экрана.
3. Панель плиток статистики можно свернуть кнопкой в строке типа движения; состояние — только на время жизни экрана (по умолчанию развёрнута).

### UC-04. Экспорт GPX
1. Сборка GPX в памяти (для треков до 50 000 точек — потоковая запись в файл).
2. Файл сохраняется в `cacheDir/exports/<name>.gpx`, выдаётся через `FileProvider`, `Intent.ACTION_SEND` с `text/xml`/`application/gpx+xml`.
3. Файлы старше 24 ч удаляются при следующем экспорте.

### UC-05. Запрос разрешений
1. Показ rationale (если `shouldShowRequestPermissionRationale` или первый раз).
2. Запрос `ACCESS_FINE_LOCATION` + `ACCESS_COARSE_LOCATION`.
3. На Android 13+ — запрос `POST_NOTIFICATIONS` (не блокирующий).
4. При «Не спрашивать больше» — экран с кнопкой «Открыть настройки приложения».

### UC-06. Интересное рядом (1.1)
**Основной поток.** 1. Экран «Запись» получает положение (последнее известное или фикс). 2. Система вычисляет ячейку сетки `GeoCell` (0.005°). 3. При смене ячейки и промахе кэша — запрос к Overpass вокруг центра ячейки (R = 1500 м), не чаще 1 раза в 15 с. 4. Ответ парсится в список объектов (≤ 60, только с тегом `wikipedia` и `name`, без `boundary`/`admin_level`, дубликаты по статье убраны). 5. Метки рисуются на карте; предыдущий список остаётся до прихода нового. 6. Тап на метку → карточка; запрос Wikipedia REST `page/summary` (кэш по `lang:Title`). 7. «Прочитать вслух» → TTS на языке статьи.
**Альтернативные потоки.** A1: нет сети / HTTP ≠ 2xx / таймаут → метки не обновляются, следующий запрос не раньше чем через 60 с. A2: статья — страница неоднозначности или 404 → «Описание недоступно», 404 кэшируется. A3: TTS не инициализировался → кнопка скрыта. A4: настройка выключена → ни одного сетевого запроса, метки убраны. A5: карточка трека → запрос вдоль полилинии (≤ 80 вершин, R = 400 м), кэш по trackId.

### UC-07. Авто-озвучка при приближении (1.1, opt-in)
**Предусловия:** `poiEnabled && poiAutoSpeak`, идёт запись (`serviceRunning`).
**Поток.** На каждом обновлении `live` (≈ 1 Гц, conflated): ячейка → кэш объектов (промах → одиночный запрос); `nextToAnnounce` — ближайший необъявленный объект ≤ 150 м; добавить в «объявленные»; получить summary; произнести «<Название>. <spokenIntro ≤ 320 символов до границы предложения>» в режиме QUEUE_ADD. Множество объявленных очищается при переходе `serviceRunning: false → true`.
**Исключения.** Ошибки сети — объект остаётся необъявленным до следующей проверки (не добавляется в множество, если список объектов не получен); ошибка TTS — логируется, аудиофокус освобождается.

### UC-08. Выбор языка (JustTracker, US-18)
**Основной поток.** 1. Первый запуск: `AppSettings.language == null` → шаг «Выберите язык», предвыбор `AppLanguage.forDevice()` (ru → RU, иначе EN). 2. «Продолжить» → `SettingsRepository.setLanguage(tag)` (DataStore, ключ `language`) → `AppLocale.apply`: `Locale.setDefault` + `AppCompatDelegate.setApplicationLocales`. 3. AppCompat пересоздаёт activity (API < 33 — только если локаль отличается; 33+ — всегда через системный LocaleManager); онбординг продолжается со шага разрешений. 4. Настройки → «Язык» → тот же путь без онбординга.
**Инварианты.** DataStore — источник истины: при каждом запуске `MainActivity` вызывает `AppLocale.sync` (если AppCompat «забыл» выбор — после restore/переустановки — он восстанавливается); `AppContainer` держит `Locale.getDefault()` равным выбору; сервис получает строки через `AppLocale.localized`. Вариант «системный» отсутствует.
**Альтернативы.** A1: язык устройства не поддерживается → предвыбор EN. A2: пользователь сменил язык приложения в системных настройках (Android 13+) → AppCompat сообщает новую локаль, но DataStore не меняется → при следующем `sync` побеждает выбор в приложении (документированное поведение; при желании обратной синхронизации — читать `getApplicationLocales` в `MainActivity` и писать в DataStore).

### UC-09. Загрузка региона офлайн-карты (US-19)
**Предусловия.** Есть внешнее хранилище (`getExternalFilesDir`), каталог загружен из `assets/maps/regions.json`.
**Основной поток.** 1. Настройки → Офлайн-карты → «Скачать» у региона → диалог (имя, размер, условие сети). 2. Подтверждение → `OfflineRegionStore.download(id)`: проверка `RegionTransitions` (absent → QUEUED / ERROR → QUEUED), проверка места (`free ≥ size + 200 МБ`), `RegionDownloader.enqueue` (DownloadManager, `<id>.map.part`, `NETWORK_WIFI` при `mapsWifiOnly`), строка в `offline_regions` со `downloadId`. 3. Поллинг статуса раз в 1 с → прогресс в UI; `STATUS_RUNNING` → DOWNLOADING; `PAUSED_WAITING_FOR_NETWORK`/`QUEUED_FOR_WIFI` → «Ожидание Wi-Fi/сети». 4. `ACTION_DOWNLOAD_COMPLETE` (receiver) или поллинг → `onDownloadFinished`: `STATUS_SUCCESSFUL` → VERIFYING → `MapFileInspector` читает заголовок → переименование в `<id>.map`, bbox/размер из заголовка → READY. 5. `readyCoverage` обновляется → `TrackMap` пересобирает `HybridTileProvider`.
**Альтернативные потоки.** A1 нет сети при постановке → DownloadManager ждёт, статус «Ожидание сети». A2 мало места → `RegionError.NO_SPACE`, строка не создаётся, Snackbar. A3 обрыв/HTTP-ошибка → `STATUS_FAILED` → ERROR(NETWORK) с кнопкой «Повторить» (`retry` → QUEUED, заново). A4 повреждённый/неполный файл → ERROR(CORRUPT), файл удалён. A5 отмена → `dm.remove` (частичный файл удалён), строка удалена. A6 процесс убит → загрузка продолжается системой; при старте `reconcile()` сверяет строки с DownloadManager и файлами (потерянные → ERROR(LOST)). A7 удаление READY → файл и строка удалены, карта области снова онлайн. A8 нет внешнего хранилища → загрузки недоступны, только импорт.

### UC-10. Импорт файла карты (US-20)
**Поток.** 1. «Импортировать файл .map» → системный `OpenDocument` (`*/*`, у `.map` нет MIME). 2. Файл копируется в `<maps>/import-<uuid>.map.part`; `MapFileInspector.inspect` → при успехе переименование в `.map`, строка READY со `source = IMPORT`, имя — из `DISPLAY_NAME` без расширения. 3. Регион используется как в UC-09.
**Альтернативы.** A1 не карта Mapsforge / ошибка чтения → файл удалён, Snackbar «Файл не является картой». A2 `.map` скопирован в папку вручную → `reconcile()` при старте создаёт строку IMPORT (`adoptFile`). A3 удаление импортированного — как у каталожного.

### UC-11. Переключение режима карты (US-22)
**Предусловия.** Онбординг завершён.
**Основной поток (настройки).** 1. Настройки → «Режим карты» → диалог с вариантами Онлайн/Офлайн и числом готовых регионов. 2. «Применить» → `MapModeController.setMode` → DataStore `map_mode` → `TrackMap` пересобирает провайдер (`HybridTileProvider.create(mode)`), в OFFLINE появляется бейдж «Офлайн-карта».
**Основной поток (смена сети).** 1. `ConnectivityObserver` меняет `online`. 2. `MapModeAdvisor.suggest`: ONLINE ∧ ¬online ∧ есть READY-регионы → предложить OFFLINE («Нет подключения…»); OFFLINE ∧ online → предложить ONLINE («Интернет снова доступен»). 3. Окно поверх текущего экрана: «Переключить» → `setMode(target)`; «Оставить как есть» → `dismissSuggestion()` запоминает текущее `online` — окно не повторяется, пока `online` не изменится.
**Альтернативы.** A1 ONLINE, нет сети, регионов нет → окно не показывается (карта — из кэша, пустые тайлы без ошибок). A2 Онбординг не завершён → окно не показывается. A3 Сеть «мигает» (captive portal, Wi-Fi без интернета) → `online` = false, пока сеть не VALIDATED; окно показывается один раз на состояние. A4 Пользователь выбрал OFFLINE без регионов → диалог предупреждает, карта пустая (кэш), бейдж виден.

## 3. Алгоритмы

### 3.1. Фильтр точек (LocationFilter)
Точка `p` принимается, если выполняются все условия относительно последней принятой точки `q` того же сегмента (для первой точки сегмента — только условие 1):
1. `p.accuracy ≤ maxAccuracyM` (по умолчанию 50 м).
2. `p.timestamp > q.timestamp`.
3. Расстояние `d = haversine(q, p)`: `d ≥ max(2 м, p.accuracy * 0.25)` **или** прошло ≥ 30 с (точка стояния сохраняется для корректного времени).
4. Правдоподобная скорость: `d / ((p.ts − q.ts)/1000) ≤ 70 м/с` (≈ 250 км/ч); иначе точка отбрасывается как выброс.
5. Если `p.speed` отсутствует, вычисляется `speed = d / dt`.

### 3.2. Дистанция
Haversine, радиус Земли `R = 6 371 008.8 м`:
```
a = sin²(Δφ/2) + cos φ1 · cos φ2 · sin²(Δλ/2)
d = 2R · atan2(√a, √(1−a))
```
Суммируется только между соседними точками одного сегмента.

### 3.3. Скорости и время
- Мгновенная скорость (`effectiveSpeed`): `Location.speed`, если она есть **и** (она > 0.5 м/с **или** смещение `d/dt ≤ 0.5 м/с`); иначе `d/dt`. Так игнорируются приёмники, сообщающие «0» при реальном движении (в т.ч. эмулятор). Отображается экспоненциально сглаженной (`α = 0.5`).
- Время движения: сумма `dt` между соседними точками сегмента, где **смещение** `d/dt > 0.5 м/с` (порог стояния). Считается по фактическому перемещению, а не по отчётной скорости.
- Средняя скорость: `distance / movingTime`. Дополнительно показывается «средняя общая» = `distance / totalTime`.
- Макс. скорость: максимум по сглаженной скорости (медиана окна из 3 точек — устраняет одиночные выбросы).
- Темп: `movingTime / distance` в мин/км, показывается для WALK/RUN.
- Время записи (1.2): `(finishedAt ?: now) − startedAt` — секундомер от «Старт» до «Стоп», паузы **включаются** (в отличие от `totalTimeMs`). На экране записи тикает по 1-секундному тикеру ViewModel, поэтому идёт и при отсутствии GPS-фиксов; в уведомлении — системный хронометр от `startedAt`.

### 3.4. Набор высоты
- Используется только `altitude` с `verticalAccuracy ≤ 15 м` (если доступна) либо любая, если `verticalAccuracy` нет.
- Сглаживание: скользящее среднее по 5 точкам.
- Порог гистерезиса: изменение засчитывается, когда накопленная разница от последнего экстремума ≥ 3 м; положительная → gain, отрицательная → loss.

### 3.6. Скорость по участкам (SpeedProfile, 1.2)
Вход: точки трека по времени. Для каждой точки `i`:
- `speed[i]` — сглаженная скорость из §3.3 (медиана окна 3) — совпадает с рядом, по которому берётся макс. скорость, поэтому «красный» конец шкалы = плитка «Макс. скорость».
- `distance[i]` — накопленная дистанция от старта; между сегментами (пауза, восстановление) разрыв не добавляется.
- `elapsed[i] = timestamp[i] − startedAt` — время с начала записи.

Цвет вершины: `fraction = clamp(speed / max(maxSpeedMps, 1 м/с), 0, 1)` → линейная интерполяция по пяти опорным цветам (`SpeedColorScale`). Отрезок `i → i+1` красится цветом вершины `i`. Тап по линии: ближайшая вершина по equirectangular-метрике → `TrackTapInfo(point, speed, distance, elapsed)`. Профиль пересчитывается при каждой эмиссии точек (1 Гц на live-экране) на `Dispatchers.Default`; O(n).

**Курсор по треку (детали).** Положение курсора — глобальный индекс вершины `g` по всем сегментам. Слайдер задаёт долю дистанции `f ∈ [0, 1]`; целевая дистанция `f · distance[n−1]`; вершина — ближайшая по накопленной дистанции (бинарный поиск в сегменте, содержащем цель; O(log n)). Обратно: `f = distance[g] / distance[n−1]` (0 при нулевой дистанции). Подпись слайдера: `elapsed[g]` и `round(100·f)` %. Значения в точке: `speed[g]`, `distance[g]`, `timestamp[g]` (время суток в зоне устройства), `altitude[g]` (может отсутствовать). Стрелки: `g ± 1` с ограничением `[0, n−1]`.

### 3.5. Классификация типа движения
Вход: список сглаженных скоростей точек движения (`speed > 0.5 м/с`). Признаки: медиана `v50`, 90-й процентиль `v90`, максимум `vmax`.

| Тип | Условие |
|-----|---------|
| WALK | `v50 < 2.0 м/с` и `v90 < 3.0` |
| RUN | `2.0 ≤ v50 < 4.5` и `v90 < 6.5` |
| BIKE | `3.0 ≤ v50 < 12` и `v90 < 16` (и не RUN) |
| CAR | `v50 ≥ 8` или `v90 ≥ 16` |
| OTHER | не подходит ни под одно правило |
| UNKNOWN | < 10 точек движения |

Правила разрешения конфликтов: проверяются сверху вниз, первое совпавшее правило побеждает; CAR проверяется до BIKE по условию `v90 ≥ 16`. Если `activityManual = true`, классификация не применяется.

### 3.6. Автоименование
`"<ActivityName> · <d MMM, HH:mm>"` в **языке приложения** (`AppLocale.current(settings)`, не в системной локали); при UNKNOWN — «Трек».

### 3.8. Выбор источника тайла (MapSourceResolver, JustTracker)
Применяется **только в режиме OFFLINE** (в ONLINE провайдер не содержит офлайн-модуля). Для тайла (z, x, y): если `z < 8` или нет READY-регионов → ONLINE (в OFFLINE это означает «кэш/аппроксимация, без сети»); иначе bbox тайла (`LatLonBox.ofTile`, Web Mercator) пересекается с bbox каждого READY-региона (границы включительно) → OFFLINE(список файлов пересечённых регионов) или ONLINE. Регионы, пересекающие антимеридиан, в каталоге разбиты на два (Дальний Восток 1/2). Проверка выполняется на каждый запрос тайла в потоке рендера и в `isDowngradedMode` провайдера (O(регионов)).

### 3.9. Рендер и кэш офлайн-тайлов (OfflineTiles, 1.0.1, ADR-17)
- **Размер тайла:** `tileSize = 512`, если `density ≥ 1.5`, иначе `256`; масштаб темы Mapsforge `scale = tileSize / 256` (штрихи, шрифты, символы). osmdroid рисует тайл в квадрате `256·density` px независимо от размера растра.
- **Потоки рендера:** `threads = clamp(cores / 2, 2, 4)`; пул хранилищ `MapFile` — `threads + 1` (ещё один для потока pre-cache osmdroid).
- **Порядок модулей в OFFLINE:** SQLite-кэш отрендеренных тайлов → аппроксимация из него (младшие зумы) → рендер (только покрытые тайлы, зум 8–20) → assets → кэш онлайн-тайлов → архивы → аппроксимация → (загрузчик отключён). Pre-cache (кольцо в 1 тайл вокруг экрана и зум −1) опрашивает те же модули в том же порядке.
- **Замена плейсхолдеров:** тайл в памяти со статусом SCALED/EXPIRED перезапрашивается по цепочке, если покрыт рендером; иначе (нет сети и нечем заменить) остаётся.
- **Кэш на диске:** каждый отрендеренный тайл кодируется в PNG в фоновом потоке и сохраняется в общий SQLite-кэш osmdroid под именем `JustTrackerOffline-<fp>`, срок 30 дней; общий лимит кэша 300 МБ с обрезкой до 240 МБ (старые по сроку — первыми).
- **Отпечаток `fp`** = первые 16 hex SHA-256 от строки `sorted(path|size|mtime)… + lang=<язык> + tile=<размер>`. Любое изменение набора READY-файлов, их содержимого, языка подписей или размера тайла даёт новое имя; при создании провайдера строки других имён `JustTrackerOffline-*` удаляются.

### 3.7. Интересное рядом: сетка, запросы, категории, близость (1.1)

| Параметр | Значение | Где |
|----------|----------|-----|
| Размер ячейки сетки | 0.005° по широте и долготе (≈ 556 м × 320 м на 55° с. ш.) | `GeoCell.SIZE_DEG` |
| Центр запроса | `((row + 0.5)·0.005, (col + 0.5)·0.005)` — не положение пользователя | `GeoCell.centerLat/Lon` |
| Радиус вокруг ячейки | 1500 м (покрытие ≥ 1200 м от реального положения) | `OverpassQl.POINT_RADIUS_M` |
| Радиус вдоль трека | 400 м | `OverpassQl.TRACK_RADIUS_M` |
| Упрощение полилинии | равномерная выборка до 80 вершин, первая и последняя сохраняются; координаты — 4 знака (`Locale.ROOT`) | `OverpassQl.simplify` |
| Лимит результатов | 200 в запросе (`out center 200` — Overpass отдаёт первые по id, не ближайшие), на экране записи — 80 ближайших к центру ячейки, в деталях — 60 ближайших к линии трека (расстояние до ближайшей вершины упрощённой полилинии) | `OverpassQl.MAX_RESULTS`, `MAX_AROUND_CELL`, `MAX_ALONG_TRACK`, `PoiProximity.nearest/nearestToLine` |
| Интервал между запросами Overpass | ≥ 15 с; после ошибки — 60 с | `PoiRepository` |
| TTL кэша | 30 мин (ячейки, треки); описания — до конца процесса, LRU 64 | `PoiRepository` |
| Радиус объявления | 150 м, ближайший, один раз за трек | `PoiProximity.ANNOUNCE_RADIUS_M` |
| Длина авто-озвучки | ≤ 320 символов, обрезка по границе предложения, если она дальше 1/4 бюджета | `PoiSummary.spokenIntro` |
| Лимит тела ответа | 2 МБ; таймауты connect 10 с / read 25 с | `Http` |

Селектор Overpass: `nwr["wikipedia"]["name"][!"boundary"][!"admin_level"]`.

Имя объекта: `name:<язык устройства>` → `name`. Статья: `wikipedia:<язык устройства>` (значение — заголовок, язык = язык устройства) → `wikipedia` (`lang:Title`). Валидация `lang`: `^[a-z]{2,3}(-[a-z]{2,10})?$`; заголовок ≤ 255 символов, без `#`, `?` и управляющих символов; `_` ↔ пробел нормализуются.

Категория (первое совпадение сверху вниз): `tourism ∈ {museum, gallery}` → MUSEUM; `amenity = place_of_worship` или `building ∈ {church, cathedral, chapel, mosque, synagogue, temple, monastery}` → WORSHIP; есть `historic` → HISTORIC; `tourism ∈ {attraction, viewpoint, artwork, theme_park}` или `amenity ∈ {theatre, arts_centre, cinema, planetarium}` → ATTRACTION; есть `natural` или `leisure ∈ {park, garden, nature_reserve}` или `landuse = forest` → NATURE; иначе PLACE.

## 5. Формат экспорта GPX 1.1

```xml
<?xml version="1.0" encoding="UTF-8"?>
<gpx version="1.1" creator="JustTracker" xmlns="http://www.topografix.com/GPX/1/1">
  <metadata><name>…</name><time>2026-09-19T10:00:00Z</time></metadata>
  <trk>
    <name>…</name>
    <type>walking|running|cycling|driving|other</type>
    <trkseg>            <!-- один trkseg на сегмент -->
      <trkpt lat="55.75" lon="37.61">
        <ele>150.2</ele>
        <time>2026-09-19T10:00:01Z</time>
        <extensions><speed>1.4</speed></extensions>
      </trkpt>
    </trkseg>
  </trk>
</gpx>
```
Время — ISO-8601 UTC с суффиксом `Z`; координаты — 6 знаков после запятой; `ele` опускается при отсутствии высоты.
