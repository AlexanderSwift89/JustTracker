# TrekLog — системная спецификация (системный аналитик)

## 1. Сценарии использования

### UC-01. Запись трека
**Актёр:** пользователь. **Предусловие:** приложение открыто на экране «Запись».
**Основной поток:**
1. Пользователь нажимает «Старт».
2. Система проверяет разрешение `ACCESS_FINE_LOCATION`; при отсутствии — UC-05.
3. Система проверяет, включён ли провайдер GPS; при выключенном — предлагает открыть настройки, сценарий приостанавливается.
4. Система создаёт запись `Track(status=RECORDING, startedAt=now)` в БД и запускает `TrackingService` в foreground с уведомлением.
5. Сервис подписывается на Fused Location Provider (интервал 1 с, минимальный 500 мс, `PRIORITY_HIGH_ACCURACY`).
6. Каждая полученная точка проходит фильтр (§3.1); принятые сохраняются в `TrackPoint`.
7. UI наблюдает БД и обновляет карту и метрики.
8. Пользователь нажимает «Стоп» → подтверждение → `Track.status=FINISHED, finishedAt=now`, статистика пересчитывается и сохраняется, сервис останавливается, открывается экран деталей.

**Альтернативные потоки:**
- 6a. Потеря сигнала GPS > 10 с: UI показывает «Поиск GPS»; сервис продолжает ждать; при восстановлении новые точки добавляются в тот же сегмент, если разрыв < 60 с, иначе открывается новый сегмент (линия не соединяется).
- 6b. Пользователь отзывает разрешение во время записи (через настройки): FLP перестаёт поставлять точки; при возврате в приложение UI показывает баннер «Разрешение отозвано» с кнопкой запроса; сервис остаётся живым до «Стоп».
- 6c. Система убивает процесс: сервис имеет `START_STICKY`; при перезапуске сервис читает из БД трек со статусом `RECORDING`/`PAUSED` и продолжает запись новым сегментом. Если сервис не перезапущен (например, force-stop), при следующем запуске UI видит трек `RECORDING` без живого сервиса и предлагает «Продолжить» / «Завершить».
- 6d. Перезагрузка устройства: сервис не перезапускается автоматически (без `RECEIVE_BOOT_COMPLETED` в MVP); поведение как в 6c при следующем запуске приложения.
- 6e. Нехватка места: `SQLiteFullException` перехватывается, запись автоматически завершается со статусом FINISHED, показывается уведомление об ошибке.
- 8a. Трек < 2 точек: трек удаляется, сообщение «Слишком мало данных».

### UC-02. Пауза / продолжение
1. «Пауза» → `Track.status=PAUSED`, сервис отписывается от FLP, но остаётся foreground; уведомление «Пауза».
2. «Продолжить» → `segmentIndex++`, подписка на FLP восстанавливается.

### UC-03. Просмотр истории и деталей
1. Список: `SELECT * FROM tracks WHERE status='FINISHED' ORDER BY startedAt DESC`.
2. Детали: загрузка всех точек трека, построение полилиний по сегментам, fit bounds с отступом 48 dp.

### UC-04. Экспорт GPX
1. Сборка GPX в памяти (для треков до 50 000 точек — потоковая запись в файл).
2. Файл сохраняется в `cacheDir/exports/<name>.gpx`, выдаётся через `FileProvider`, `Intent.ACTION_SEND` с `text/xml`/`application/gpx+xml`.
3. Файлы старше 24 ч удаляются при следующем экспорте.

### UC-05. Запрос разрешений
1. Показ rationale (если `shouldShowRequestPermissionRationale` или первый раз).
2. Запрос `ACCESS_FINE_LOCATION` + `ACCESS_COARSE_LOCATION`.
3. На Android 13+ — запрос `POST_NOTIFICATIONS` (не блокирующий).
4. При «Не спрашивать больше» — экран с кнопкой «Открыть настройки приложения».

### UC-06. Интересное рядом (1.1)
**Основной поток.** 1. Экран «Запись» получает положение (последнее известное или фикс). 2. Система вычисляет ячейку сетки `GeoCell` (0.005°). 3. При смене ячейки и промахе кэша — запрос к Overpass вокруг центра ячейки (R = 1500 м), не чаще 1 раза в 15 с. 4. Ответ парсится в список объектов (≤ 60, только с тегом `wikipedia` и `name`, без `boundary`/`admin_level`, дубликаты по статье убраны). 5. Метки рисуются на карте; предыдущий список остаётся до прихода нового. 6. Тап на метку → карточка; запрос Wikipedia REST `page/summary` (кэш по `lang:Title`). 7. «Прочитать вслух» → TTS на языке статьи.
**Альтернативные потоки.** A1: нет сети / HTTP ≠ 2xx / таймаут → метки не обновляются, следующий запрос не раньше чем через 60 с. A2: статья — страница неоднозначности или 404 → «Описание недоступно», 404 кэшируется. A3: TTS не инициализировался → кнопка скрыта. A4: настройка выключена → ни одного сетевого запроса, метки убраны. A5: карточка трека → запрос вдоль полилинии (≤ 80 вершин, R = 400 м), кэш по trackId.

### UC-07. Авто-озвучка при приближении (1.1, opt-in)
**Предусловия:** `poiEnabled && poiAutoSpeak`, идёт запись (`serviceRunning`).
**Поток.** На каждом обновлении `live` (≈ 1 Гц, conflated): ячейка → кэш объектов (промах → одиночный запрос); `nextToAnnounce` — ближайший необъявленный объект ≤ 150 м; добавить в «объявленные»; получить summary; произнести «<Название>. <spokenIntro ≤ 320 символов до границы предложения>» в режиме QUEUE_ADD. Множество объявленных очищается при переходе `serviceRunning: false → true`.
**Исключения.** Ошибки сети — объект остаётся необъявленным до следующей проверки (не добавляется в множество, если список объектов не получен); ошибка TTS — логируется, аудиофокус освобождается.

## 3. Алгоритмы

### 3.1. Фильтр точек (LocationFilter)
Точка `p` принимается, если выполняются все условия относительно последней принятой точки `q` того же сегмента (для первой точки сегмента — только условие 1):
1. `p.accuracy ≤ maxAccuracyM` (по умолчанию 50 м).
2. `p.timestamp > q.timestamp`.
3. Расстояние `d = haversine(q, p)`: `d ≥ max(2 м, p.accuracy * 0.25)` **или** прошло ≥ 30 с (точка стояния сохраняется для корректного времени).
4. Правдоподобная скорость: `d / ((p.ts − q.ts)/1000) ≤ 70 м/с` (≈ 250 км/ч); иначе точка отбрасывается как выброс.
5. Если `p.speed` отсутствует, вычисляется `speed = d / dt`.

### 3.2. Дистанция
Haversine, радиус Земли `R = 6 371 008.8 м`:
```
a = sin²(Δφ/2) + cos φ1 · cos φ2 · sin²(Δλ/2)
d = 2R · atan2(√a, √(1−a))
```
Суммируется только между соседними точками одного сегмента.

### 3.3. Скорости и время
- Мгновенная скорость (`effectiveSpeed`): `Location.speed`, если она есть **и** (она > 0.5 м/с **или** смещение `d/dt ≤ 0.5 м/с`); иначе `d/dt`. Так игнорируются приёмники, сообщающие «0» при реальном движении (в т.ч. эмулятор). Отображается экспоненциально сглаженной (`α = 0.5`).
- Время движения: сумма `dt` между соседними точками сегмента, где **смещение** `d/dt > 0.5 м/с` (порог стояния). Считается по фактическому перемещению, а не по отчётной скорости.
- Средняя скорость: `distance / movingTime`. Дополнительно показывается «средняя общая» = `distance / totalTime`.
- Макс. скорость: максимум по сглаженной скорости (медиана окна из 3 точек — устраняет одиночные выбросы).
- Темп: `movingTime / distance` в мин/км, показывается для WALK/RUN.

### 3.4. Набор высоты
- Используется только `altitude` с `verticalAccuracy ≤ 15 м` (если доступна) либо любая, если `verticalAccuracy` нет.
- Сглаживание: скользящее среднее по 5 точкам.
- Порог гистерезиса: изменение засчитывается, когда накопленная разница от последнего экстремума ≥ 3 м; положительная → gain, отрицательная → loss.

### 3.5. Классификация типа движения
Вход: список сглаженных скоростей точек движения (`speed > 0.5 м/с`). Признаки: медиана `v50`, 90-й процентиль `v90`, максимум `vmax`.

| Тип | Условие |
|-----|---------|
| WALK | `v50 < 2.0 м/с` и `v90 < 3.0` |
| RUN | `2.0 ≤ v50 < 4.5` и `v90 < 6.5` |
| BIKE | `3.0 ≤ v50 < 12` и `v90 < 16` (и не RUN) |
| CAR | `v50 ≥ 8` или `v90 ≥ 16` |
| OTHER | не подходит ни под одно правило |
| UNKNOWN | < 10 точек движения |

Правила разрешения конфликтов: проверяются сверху вниз, первое совпавшее правило побеждает; CAR проверяется до BIKE по условию `v90 ≥ 16`. Если `activityManual = true`, классификация не применяется.

### 3.6. Автоименование
`"<ActivityName> · <dd MMM yyyy, HH:mm>"` в локали пользователя; при UNKNOWN — «Трек».

### 3.7. Интересное рядом: сетка, запросы, категории, близость (1.1)

| Параметр | Значение | Где |
|----------|----------|-----|
| Размер ячейки сетки | 0.005° по широте и долготе (≈ 556 м × 320 м на 55° с. ш.) | `GeoCell.SIZE_DEG` |
| Центр запроса | `((row + 0.5)·0.005, (col + 0.5)·0.005)` — не положение пользователя | `GeoCell.centerLat/Lon` |
| Радиус вокруг ячейки | 1500 м (покрытие ≥ 1200 м от реального положения) | `OverpassQl.POINT_RADIUS_M` |
| Радиус вдоль трека | 400 м | `OverpassQl.TRACK_RADIUS_M` |
| Упрощение полилинии | равномерная выборка до 80 вершин, первая и последняя сохраняются; координаты — 4 знака (`Locale.ROOT`) | `OverpassQl.simplify` |
| Лимит результатов | 200 в запросе (`out center 200` — Overpass отдаёт первые по id, не ближайшие), на экране записи — 80 ближайших к центру ячейки, в деталях — 60 ближайших к линии трека (расстояние до ближайшей вершины упрощённой полилинии) | `OverpassQl.MAX_RESULTS`, `MAX_AROUND_CELL`, `MAX_ALONG_TRACK`, `PoiProximity.nearest/nearestToLine` |
| Интервал между запросами Overpass | ≥ 15 с; после ошибки — 60 с | `PoiRepository` |
| TTL кэша | 30 мин (ячейки, треки); описания — до конца процесса, LRU 64 | `PoiRepository` |
| Радиус объявления | 150 м, ближайший, один раз за трек | `PoiProximity.ANNOUNCE_RADIUS_M` |
| Длина авто-озвучки | ≤ 320 символов, обрезка по границе предложения, если она дальше 1/4 бюджета | `PoiSummary.spokenIntro` |
| Лимит тела ответа | 2 МБ; таймауты connect 10 с / read 25 с | `Http` |

Селектор Overpass: `nwr["wikipedia"]["name"][!"boundary"][!"admin_level"]`.

Имя объекта: `name:<язык устройства>` → `name`. Статья: `wikipedia:<язык устройства>` (значение — заголовок, язык = язык устройства) → `wikipedia` (`lang:Title`). Валидация `lang`: `^[a-z]{2,3}(-[a-z]{2,10})?$`; заголовок ≤ 255 символов, без `#`, `?` и управляющих символов; `_` ↔ пробел нормализуются.

Категория (первое совпадение сверху вниз): `tourism ∈ {museum, gallery}` → MUSEUM; `amenity = place_of_worship` или `building ∈ {church, cathedral, chapel, mosque, synagogue, temple, monastery}` → WORSHIP; есть `historic` → HISTORIC; `tourism ∈ {attraction, viewpoint, artwork, theme_park}` или `amenity ∈ {theatre, arts_centre, cinema, planetarium}` → ATTRACTION; есть `natural` или `leisure ∈ {park, garden, nature_reserve}` или `landuse = forest` → NATURE; иначе PLACE.

## 5. Формат экспорта GPX 1.1

```xml
<?xml version="1.0" encoding="UTF-8"?>
<gpx version="1.1" creator="TrekLog" xmlns="http://www.topografix.com/GPX/1/1">
  <metadata><name>…</name><time>2026-09-19T10:00:00Z</time></metadata>
  <trk>
    <name>…</name>
    <type>walking|running|cycling|driving|other</type>
    <trkseg>            <!-- один trkseg на сегмент -->
      <trkpt lat="55.75" lon="37.61">
        <ele>150.2</ele>
        <time>2026-09-19T10:00:01Z</time>
        <extensions><speed>1.4</speed></extensions>
      </trkpt>
    </trkseg>
  </trk>
</gpx>
```
Время — ISO-8601 UTC с суффиксом `Z`; координаты — 6 знаков после запятой; `ele` опускается при отсутствии высоты.
