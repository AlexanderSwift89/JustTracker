# TrekLog — промпты для ролей команды

Проект: **TrekLog** — Android-приложение для записи GPS-треков с отображением на карте, статистикой и историей. MVP полностью офлайн, без бэкенда и без авторизации.

Каждый промпт ниже — самодостаточное задание для роли. Общий контекст (вставляется в начало каждого промпта):

> **Контекст проекта.** Мы разрабатываем Android-приложение TrekLog. Пользователь вручную запускает и останавливает запись GPS-трека. Трек рисуется на карте, сохраняется локально на устройстве. Пользователь может смотреть текущий трек, историю треков на карте, мгновенную и среднюю скорость, тип движения (пешком / бег / велосипед / автомобиль — определяется автоматически, с возможностью ручного изменения) и другую полезную статистику. MVP: без бэкенда, без регистрации, все данные хранятся на устройстве. Целевая платформа: Android 8.0+ (API 26+), публикация в Google Play. Стек: Kotlin, Jetpack Compose, Room, Fused Location Provider, osmdroid (OpenStreetMap). Язык документации — русский; идентификаторы в коде и строки по умолчанию — английский, локализация UI на русский.

## 4. Архитектор

**Роль:** Ты — архитектор мобильных приложений с опытом построения offline-first Android-приложений и работы с фоновой геолокацией.

**Задача:** Спроектировать архитектуру TrekLog.

**Что нужно сделать:**
1. Выбрать и обосновать стек: Kotlin, Compose, Room, Coroutines/Flow, Fused Location Provider, osmdroid (обосновать выбор OSM против Google Maps SDK для MVP: без API-ключа, без биллинга), Hilt или ручной DI (обосновать).
2. Описать слои: UI (Compose + ViewModel) → Domain (use cases, чистые модели, алгоритмы) → Data (Room, LocationRepository, TrackRepository). Правила зависимостей.
3. Спроектировать Foreground Service для записи: жизненный цикл, тип `location`, уведомление, восстановление после kill процесса, взаимодействие с ViewModel через репозиторий (single source of truth в БД), обработка Doze и battery optimization.
4. Спроектировать модель данных: Track, TrackPoint, сегменты (паузы), вычисляемая статистика; индексы; миграции.
5. Описать алгоритмы: фильтрация GPS-шума (accuracy threshold, отбрасывание выбросов по скорости), расчёт дистанции (haversine), средней скорости (moving vs total), набора высоты (с порогом), автоопределение типа движения по распределению скоростей.
6. Описать экспорт GPX и стратегию тестирования (unit для алгоритмов, Room in-memory, инструментальные для сервиса).
7. Составить ADR (Architecture Decision Records) на ключевые решения.

**Формат результата:** `docs/05_architecture.md` с диаграммами (Mermaid), структурой пакетов и ADR.
