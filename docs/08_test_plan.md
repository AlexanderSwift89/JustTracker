## 2. Тестовые данные

Синтетические треки генерируются в тестах функцией `syntheticTrack(speedMps, seconds, segment, jitter)`:
- пешком 1.4 м/с, бег 3.0 м/с, велосипед 6.0 м/с, авто 15 м/с;
- «город с остановками» — 80 % точек 4 м/с + 20 % 20 м/с → должен классифицироваться как CAR;
- шум: ±20 % по скорости, ±0.2 м по координатам, единичный выброс 40 м/с.

Для ручного тестирования на эмуляторе — скрипт подачи точек (PowerShell, **обязательно инвариантная культура — иначе `55,75` с запятой ломает `geo fix`**):
```powershell
$adb="D:\Android_sdk\platform-tools\adb.exe"; $lat=55.7558; $lon=37.6173
for($i=0;$i -lt 60;$i++){ $lat += 0.000027; $lon += 0.000015
  $s="$($lon.ToString('F6',[cultureinfo]::InvariantCulture)) $($lat.ToString('F6',[cultureinfo]::InvariantCulture)) 150"
  & $adb emu geo fix $s.Split(' ') | Out-Null; Start-Sleep 1 }
```
Шаг 0.000027° широты ≈ 3 м/с (бег). Для «пешком» — 0.000012, для «авто» — 0.00012.

Особенность эмулятора: `Location.speed` ≈ 0 всегда — именно поэтому введена эвристика `effectiveSpeed` (§3.3 системной спецификации).

## 5. Открытые наблюдения

- **OBS-02 (1.1).** Публичный Overpass отвечает `504` под нагрузкой (поймано при smoke-тесте) — обрабатывается backoff'ом 60 с, метки не обновляются. Если жалобы в отзывах — добавить второй инстанс (`overpass.kumi.systems`) как fallback.
- **OBS-03 (1.1).** В центре мегаполиса в полосе 400 м вокруг 500-метрового трека Overpass возвращает > 120 объектов; после ограничения до 60 ближайших карта всё ещё плотная. Кандидат на 1.2: кластеризация или фильтр по категориям.
- **OBS-04 (1.1).** На устройстве с локалью `en` название берётся из `name:en`, а статья — из `wikipedia` (часто `ru:`), поэтому имя и описание могут быть на разных языках. Это ожидаемо по спецификации (§3.7); улучшение — запрашивать `langlinks` для языка устройства.

- **OBS-05 (JT) — закрыто в 1.0.1.** Подписи офлайн-карты на плотных экранах были крупными и размытыми: тема Mapsforge масштабировалась по плотности (`AndroidGraphicFactory` → `DisplayModel.deviceScaleFactor`), а тайл 256 px затем ещё раз растягивался osmdroid по DPI. Теперь при плотности ≥ 1.5 тайлы рендерятся размером 512 px, а итоговый масштаб темы равен `tileSize/256` (`OfflineRenderTheme`, ADR-17); размеры подписей совпадают с онлайн-картой (проверено на эмуляторе 420 dpi).
- **OBS-09 (1.0.1).** Pre-cache osmdroid рендерит кольцо вокруг экрана и зум −1 в фоне; на экране записи при следовании за пользователем это постоянная фоновая нагрузка (как у онлайн-загрузки, но CPU вместо сети). Проверить расход батареи в TC-90 на реальном устройстве; при жалобах — отключать pre-cache офлайн-модуля во время записи.
- **OBS-06 (JT).** В тёмной теме офлайн-карта инвертируется вместе с онлайн-тайлами: вода становится коричневой. Кандидат: тёмная render-тема Mapsforge вместо `INVERT_COLORS` для офлайн-тайлов.
- **OBS-07 (JT).** В `malta.map` встречается подпись с префиксом языка («deTor am Leuchtturm») независимо от выбранного языка — особенность данных файла, не приложения.
- **OBS-08 (JT).** DownloadManager на эмуляторе с Google APIs иногда пишет `PAUSED_WAITING_FOR_NETWORK` при включённом Wi-Fi на несколько секунд после постановки — статус «Ожидание сети» мигает; на реальном устройстве проверить.

- **OBS-10 (1.0.2).** Высота в приложении и в GPX `<ele>` — над эллипсоидом WGS84, как её отдаёт Android (`Location.getAltitude()`), а не над уровнем моря, которую подразумевают GPX и топокарты: в центре европейской России показания выше на ≈ 14–16 м (ондуляция геоида). На набор/сброс не влияет. Кандидат: пересчёт при показе и экспорте через `androidx.core:core-location-altitude` (`AltitudeConverterCompat`, стабильная 1.0.0, модель геоида в библиотеке, все API) — новая зависимость, отдельное решение.
- **OBS-11 (1.0.2).** Эмулятор Pixel 7 Pro (API 34, Google Play, software GPU, 2 ГБ) на машине разработки после загрузки несколько минут отвечает «Process system / System UI isn't responding» и выдаёт ANR любому приложению при холодном старте debug-сборки (интерпретатор) — это нагрузка системы, не приложения (в `CriticalEventLog` ANR у сервисов Google). Для проверок поворота ждать успокоения системы или использовать образ без Google Play. Повторное тестирование 1.0.2 выполнено на том же образе с `-gpu host -no-window -feature -Vulkan -cores 4`: программный рендер (swiftshader) падал с «bad color buffer handle», а эмулятор, запущенный из песочницы инструмента разработки, не мог создавать потоки — запускать из обычной оболочки. В этом режиме системных ANR не было.
- **OBS-01.** На медленном эмуляторе (software GPU) дважды наблюдался «фантомный» клик через ~8 с после `adb input tap` (один раз запустил запись, один раз завершил). В трёх последующих попытках не воспроизвёлся; в коде источник не найден (все команды сервису логируются в debug). Требуется проверка на реальном устройстве; если воспроизведётся — добавить debounce на кнопки Старт/Стоп.
